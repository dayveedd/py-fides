How a purchase runs

Five steps, one record. The money moves last.

The console narrates each step as it happens, so a person can follow an agent’s purchase the way they would read a statement.

  1. The person in charge sets a spending limit and signs it.

  2. The buying and selling agents settle a price and a deadline, and the seller names the file’s fingerprint.

  3. The buyer’s money is set aside. The seller can see it is there but cannot touch it.

  4. An automatic checker compares what arrived with what was promised.

  5. If they match, the seller is paid and a receipt is issued. If not, nothing moves.

The gap, and the fix

Release on proof.

Today an agent either pays first and hopes, or a person approves every purchase. Neither scales. With pyFides the money waits where everyone can see it, and moves only when the file that arrived is the file that was promised.

Pay first

The file is wrong, or never comes.

Funds have already moved. Getting them back is a support ticket, not a protocol.

Trust the agent

One injected prompt, one bad purchase.

Without a signed limit, the agent’s own judgement is the only control.

With pyFides

Capped, held, released on proof.

The limit is signed, the money waits, and it moves only when the hashes agree.
